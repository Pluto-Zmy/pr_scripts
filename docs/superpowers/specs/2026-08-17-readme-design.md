# pr_scripts README 设计说明

## 目标

为 `pr_scripts` 编写一份中文 README，使 Premiere Pro ExtendScript 使用者能够理解三份脚本的用途、运行条件、操作步骤和注意事项，并将完整项目推送到 GitHub 仓库 `Pluto-Zmy/pr_scripts`。

## 内容结构

README 采用面向使用者的实用型结构：

1. 项目简介与适用环境。
2. 项目结构和三份主要脚本的功能概览。
3. 安装、调试与运行步骤。
4. 每份脚本的前置条件、行为和输出说明。
5. `PlaceMarkerSegments.js` 所需的序列标记、素材命名及 V5/V6 轨道约定。
6. 风险提示、错误处理和常见问题。

## 脚本定位

- `GetAllProjectItem.js`：遍历项目根目录下的指定素材箱，查找 `区界.wav`，并将已验证代码中的硬编码数值 `10` 作为时间参数传给活动序列第一条音频轨道的 `overwriteClip`；文档只记录行为，不修改或重新解释代码。
- `PrintBgmStartTime.js`：读取活动序列指定音频轨道中的所有剪辑，并在 ExtendScript 控制台打印名称和起始秒数；当前入口调用读取第二条音频轨道。
- `PlaceMarkerSegments.js`：根据活动序列标记点生成时间段，按 `GLT_P0_<序号>_BASE` 与 `GLT_P0_<序号>_MASK` 命名查找唯一素材，并分别覆盖写入 V5、V6。

三份脚本均作为主要脚本呈现，不使用“示例”“辅助”或“实验”标签。

## 准确性与边界

- 只描述当前代码已经实现的行为，不承诺未实现的兼容性或自动安装能力。
- 明确 Premiere Pro、活动项目和活动序列是运行前提。
- 明确脚本中的素材名、轨道索引和时间点为当前硬编码配置，修改前应了解 Premiere Pro 的零基索引。
- 对可能覆盖时间线已有内容的操作给出醒目提示。
- 不逐函数编写 API 手册，以避免 README 过长和后续文档漂移。

## Git 发布方式

当前目录尚未初始化 Git，目标远端仓库为空。实施时将：

1. 以 `main` 为默认分支初始化仓库。
2. 纳入三份脚本、VS Code 调试配置、README 和本设计说明。
3. 检查 README 内容、Git diff 和工作区状态。
4. 创建清晰的初始提交。
5. 添加目标仓库为 `origin` 并直接推送 `main`。

本机没有 GitHub CLI，因此不创建拉取请求；直接推送符合用户明确提出的“推送到仓库”要求。
