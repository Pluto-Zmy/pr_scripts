# A2 BGM 间隙等距重排设计说明

## 目标

新增 `RedistributeBgmGaps.js`：在活动序列中，保持 A2 上第 1～6 首和最后一首音乐的位置不变，
把中间各首音乐之间的间隙重排为等长，整条新排列写入 A3。A2 全程只读。

## 背景与实测数据

实测对象：`曲靖-洛阳_main.prproj`（父目录）中的主序列 `曲靖—洛阳_main`。

- A2 当前有 **58 个**音频剪辑，序列总长约 13031.5 秒。A1 上有 6 个 `区界.wav`。
- 仓库根目录的 `bgm.txt` 只有 42 条，且其中的起始秒已与工程现状不符（例如第 42 条），
  **不作为数据源**。脚本一律读取 Premiere 的实时数据。
- 主序列目前只有 A1、A2 两条音频轨，**A3 尚不存在**，需要用户先在 Premiere 中
  `序列 → 添加轨道 → 音频轨 1 条`。ExtendScript 无法创建轨道。
- 当前间隙分布不均匀，分四段：第 1～6 首首尾相接（间隙 0）；第 7～16 首之间 0.5～2.0 秒；
  第 17～26 首之间 0.083 秒（2 帧）；第 27～58 首之间又回到首尾相接。
- A2 上不存在重叠剪辑，因此重排只需移动，不需要裁剪任何素材。

## 计算方式

固定窗口为「第 6 首的结束点」到「最后一首（第 58 首）的开始点」，用户要求这两端不动，
所以等长间隙只有一个解：

```text
gap = (窗口长度 − 中间各首时长之和) / (中间条数 + 1)
```

按实测数据：窗口 11415.083 秒，中间 51 首时长合计 11398.667 秒，共 52 个间隙
（中间每首之前一个、最后一首之前一个），得到 **gap = 0.315705 秒**（取整到采样栅格后为
15153 个采样，0.315688 秒）；第 7～57 首相对现在整体前移 0.3～12.3 秒，位移最大的是
第 16 首（约 −12.3 秒）。

间隙对齐到**落位栅格** = 序列帧格（`sequence.timebase`）与采样栅格（由源轨现有时间点
反推）的最小公倍数。**这一点是实机跑出来的教训**：Premiere 会把剪辑位置吸附到序列帧格上，
只对齐采样栅格时，请求点被吸附了 248724000 ticks（47 个采样，约 0.98 毫秒），
使实测间隙互相差最多一帧。

可用空隙先切成整数个落位栅格单位，除不尽的余数**均匀摊到各个间隙上**（每个多一格，
Bresenham 式分布）。因此全部间隙只相差一格；显式间隙（中间每首之前各一个）与最后一个
间隙（最后一首之前，由固定端点决定）分别记账。本例：985 帧空隙 ÷ 52 个间隙 = 18 帧 × 3 +
19 帧 × 49，相差约 16.7 毫秒。

源轨任一剪辑的时间点不在落位栅格上时，脚本返回错误而不是硬排 —— 否则位置仍会被吸附，
间隙就不等了。

## 脚本行为

`RedistributeBgmGaps.js`，顶部 `CONFIG` 暴露参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `"report"` | `"report"` 只试算并打印，不做任何修改；`"write"` 才写入 A3 |
| `keepHead` | `6` | 开头保持不动的首数 |
| `keepTail` | `1` | 结尾保持不动的首数 |
| `sourceTrack` | `2` | 源音频轨（1 起，对应 A2），只读 |
| `targetTrack` | `3` | 目标音频轨（1 起，对应 A3） |
| `autoMuteSource` | `false` | 写入后是否自动静音源轨，默认关闭 |

流程：

1. 读取活动序列的源轨全部剪辑（start / end / 源 in / 源 out / 素材），按 start 排序，
   并读取序列的 `timebase` 作为落位栅格。校验：条数 ≥ `keepHead + keepTail + 1`、
   时间不重叠、源轨存在、`timebase` 可读、所有时间点都在落位栅格上。
2. 校验目标轨：轨道不存在 → 提示先添加轨道并中止；轨道已有剪辑 → 弹窗询问
   「清空目标轨后重写」还是「中止」，清空只对目标轨调用 `TrackItem.remove(0, 0)`。
3. 计算 `gap` 与每一首的新 start（见上节）。
4. 把逐条 before/after 对照表与摘要（间隙值、会移动的条数、最大位移）写入 ExtendScript
   控制台；`"write"` 模式下再打印一行醒目的 `===== WRITE 模式 =====` 横幅，然后继续。
5. 落位：逐条 `overwriteClip` 写入目标轨。写之前先把素材的源 in/out 设为源剪辑的源
   in/out 以限定长度，避免覆盖掉刚放好的相邻剪辑；落位后校正新剪辑的 start / end。
   任一条失败立即停止，报告是第几条并提示撤销。
6. 复读目标轨校验：条数、每条 start 与计划一致、相邻间隙全部等于 `gap`。任何不符都打印
   出来，供第一次运行时确认 Premiere 是否对位置做了额外量化。

## 安全边界

- 代码中 `remove` 与 `overwriteClip` 只对目标轨调用；源轨只出现在读取路径上。
- `"report"` 模式下脚本不做任何写操作，便于先核对数值。
- 放行闸门是 `CONFIG.mode` 开关本身：它必须手动改文件才能打开。脚本**不弹确认窗** ——
  Premiere 25.5 的 ExtendScript 里没有可用的模态确认对话框（全局 `confirm` 抛
  `Not Enough Parameters`，ScriptUI 的 `Window` 不存在，均在本机实测过）。
- 不自动静音源轨（默认），只在摘要中提醒 A2 与 A3 会同时出声，需要手动处理。

## 验收标准

1. `"report"` 模式输出与离线预算一致：间隙 18 帧（0.3000 秒）/ 19 帧（0.3167 秒）、
   中间 51 条、首末不动、最大位移第 16 首 −12.300 秒。
2. `"write"` 模式的复读校验无报错：目标轨 58 条，第 1～6 首与最后一首的 start 与源轨相同，
   每个显式间隙只能是 18 或 19 帧且 19 帧的个数正确，最后一个间隙不超过「基础格数 + 未摊出的格数
   + 一格」，落位偏差为 0。
3. 源轨未被修改：可用 `PrintBgmStartTime.js` 在写入前后各输出一次 A2，两份输出一致。
4. 目标轨不存在时给出明确的中文提示并中止，而不是抛出未处理异常。

## 后续影响

`PlaceBgmInfoBars.js` 当前入口 `placeBgmInfoBars(3, 2, 5)` 读取 A2。由于 A2 不变，
BGM 信息条无需重新放置。若日后改用 A3 作为生效音轨，需要把该调用的音频轨参数改为 3。
